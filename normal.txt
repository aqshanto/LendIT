I'm building a small practice web app. Stack: Python Flask, Flask-SQLAlchemy with SQLite,
Flask-Login, Jinja templates, Bootstrap 5 via CDN.

App: LendIt: Department Equipment Loan Desk. Features:
Time limit: 3 hours (19:00 → 22:00). Solo. AI tools allowed. Stop when the timer ends.

Scenario

A university department lends equipment to students — projectors, cameras, lab kits, tripods. Right now it's tracked in a paper register, so nobody knows what's available without walking to the office, and items go missing because no one records who has what. Build a web app that replaces the register.

Required features

R1. Public catalogue (no login needed)
Anyone can see the equipment list: name, category, description, and current state (Available / On loan). Search by name and filter by category. Logged-out visitors must not see who borrowed anything.

R2. Accounts and roles
Signup, login, logout. Two roles: student (default) and admin. How the first admin gets created is your design decision — document it in the README so a judge can log in as admin.

R3. Student actions

Request an item that is currently Available, with a "return by" date that must be in the future, plus an optional note.
A student may hold at most 2 active requests (pending or approved) at any time. The third is refused with a clear message.
Cancel their own request while it is still pending.
A "My requests" page showing each request with its status: Pending / Approved / Rejected / Returned / Cancelled.

R4. Admin actions

Add, edit and delete equipment items.
See all pending requests and approve or reject each one.
Approving sets the item to On loan. Approving a request for an item that is already on loan must be refused.
Mark an approved loan as Returned, which frees the item.

R5. Enforcement, not just hidden buttons
Every rule above must hold when someone types the URL directly. A student must not be able to approve a request, delete an item, or cancel someone else's request by guessing an address.

R6. Overdue
On the admin page, an approved loan whose return-by date has passed shows in red with an "Overdue" badge. Returned loans never count as overdue.

Bonus (only if the required list is complete and tested)

Admin dashboard counts (items, on loan, overdue, pending requests) · request history per item · item photo upload · CSV export of current loans.
